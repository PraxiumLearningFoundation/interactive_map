Three versions of clay

Same hue, three lightness values. The question is which one carries text and button labels. Headings are unaffected — at 2.2rem and 1.6rem they clear the large-text threshold in all three. Ratios below are measured against the live palette, not estimated.

The candidates

The middle value is the tempting one — a small nudge that looks like it should be enough. It isn't, and that's the useful thing to see.

As built
#A3826C · L 53%
The current brand value. Fine as a surface fill and for large headings. Fails as text or as a button ground.
Nudged
#8D6A52 · L 44%
Visibly darker, close to the original. Reaches 4.23:1 — still short of 4.5:1, so it fails while looking like it shouldn't.
Corrected
#85624B · L 41%
Clears AA in both directions — as text on paper, and as a fill under white labels. Same hue family, reads as the same brand.

What I'd pick

Split the role rather than replacing the color. Keep #A3826C as the display value — h3, h4, large numerals, decorative fills, the announcement bar. It's the color the foundation already recognises as theirs, and at those sizes it's compliant.

Introduce #85624B as a separate token used only where the text is small or a label sits on top: paragraph links, button fills, form accents, anything under 24px. Two tokens, one hue, no visible rebrand.

The reason not to take the nudged value: at 4.23:1 it fails the threshold while looking like a fix, which is worse than either extreme. You'd carry the same problem with less of the original color to show for it.

Whichever you choose, the token file ships with both defined and a single line that selects between them, so the decision stays reversible.

Ratios calculated per WCAG 2.1 relative luminance. AA requires 4.5:1 for text under 24px (or under 18.66px bold), and 3:1 for larger text and UI components.
